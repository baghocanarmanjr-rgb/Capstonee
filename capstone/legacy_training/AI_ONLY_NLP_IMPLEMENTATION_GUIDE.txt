AI-ONLY PR–PO NLP IMPLEMENTATION
================================

Purpose
-------
The PR–PO NLP Verification module is the only discrepancy-detection stage.
The deployed trained model is the sole source of the final result.

Final status classes learned by the model
-----------------------------------------
1. Acceptable
2. Needs Review
3. Needs Recanvass
4. Reject

Primary discrepancy types learned by a second trained classifier
----------------------------------------------------------------
- No discrepancy
- Minor wording or spelling difference
- Incomplete or ambiguous description
- Specification mismatch
- Quantity mismatch
- Unit mismatch
- Missing item description
- Different item
- General discrepancy (from legacy manually labelled binary records)

Runtime decision behavior
-------------------------
- The final result is model.predict() from the trained four-class status model.
- Confidence is the trained model probability for its selected class.
- The primary issue is model.predict() from the trained issue classifier.
- No procurement rule overrides the model.
- No 20%/80% or other weighted hybrid score is used.
- No manually written confidence threshold converts one class to another.
- No rule-based fallback creates a result.
- If the model or FastText file is missing/corrupt, verification stops and
  displays an error. No NLP record is inserted.

Training data
-------------
- All valid item descriptions dynamically read from all sheets of
  data/COA_Inventory_Dataset.xlsx.
- 838 unique usable COA item descriptions in the bundled workbook.
- 6,704 controlled PR–PO examples generated from the COA records.
- 20 existing manually labelled PR–PO examples.
- 6,724 final training pairs.

Model inputs
------------
The approved PR and PO items are serialized with:
- item description/specification
- quantity
- unit of measure

FastText supplies COA-domain subword embeddings. Generic pair-comparison
measurements are included as input features, but they never decide or override
the result; the trained Logistic Regression model learns their weights.

Important limitation
--------------------
The COA workbook does not contain real historical PR–PO outcome labels. The
COA-derived pairs are controlled synthetic examples. The evaluation is useful
for development, but it is not proof that the model will detect every possible
future real-world discrepancy. No honest AI system can guarantee this.

For stronger external validity, collect and review real PR–PO outcomes, label
them using the four status classes and discrepancy types, add them to the
training dataset, retrain, and evaluate on a separate untouched real test set.

Legacy data
