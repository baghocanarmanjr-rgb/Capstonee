How the deployed FastText model controls verification

StageAI-only behavior
Model-selection evidenceTF-IDF + Logistic Regression, FastText + Logistic Regression, and frozen DistilBERT embeddings + Logistic Regression are trained and evaluated using the same group-held-out records. The comparison is retained in the installed model manifest.
Selected modelFastText is retained as the June-selected deployment approach. The current Colab code expands its training with semantic requirement wording, synonyms, minimum/maximum/exact/range relationships, OCR-like text, COA terminology, and optional validated staff pairs.
Model inputThe approved PR and PO are serialized in natural language with item descriptions, specifications, quantities, units, and other meaningful fields. FastText produces separate PR and PO embeddings plus learned pair-comparison features.
Final decisionA trained FastText-based status classifier directly predicts Acceptable, Needs Review, Needs Recanvass, or Reject. No runtime rule changes that result.
Discrepancy explanationA separately trained FastText-based issue classifier predicts the primary issue. No hardcoded issue selector or transformer fallback is used.
Failure behaviorIf the trained FastText package cannot load, verification stops and creates no result.
Evaluation limitation: Generated and COA-derived examples are controlled training data. Report the held-out per-class metrics and add real reviewed PR–PO outcomes for stronger external validation.
